## 1. ภาพรวมเส้นทางข้อมูล

```
ตราชั่ง → (t, w) ทีละจุด                                                 (หัวข้อ 10)
   │
   ├─ [ช่วงก่อนวัด]  ถ้าตั้งไว้ — ข้อมูลใช้ดูความพร้อม ไม่นำไปคิดผล        (หัวข้อ 7)
   │
   └─ [ช่วงวัดจริง]  เริ่มนับเวลาใหม่จาก 0
        1. ทิ้งข้อมูลช่วงแรก (2 s)
        2. คำนวณ slope = flow ขณะนั้น                                   (หัวข้อ 3)
        3. วิธีจับ ตัดสินว่า "จบ 1 ช่วงวัดหรือยัง"                         (หัวข้อ 4)
        4. อัปเดตสถิติของทุกช่วงวัด                                      (หัวข้อ 5)
        5. ตัดสิน PASS / FAIL                                          (หัวข้อ 6)
   จบขั้น → ถามผู้ใช้ว่าเก็บผลหรือไม่                                     (หัวข้อ 11)
```

`t` = เวลา (วินาที), `w` = น้ำหนักบนตราชั่ง (กรัม)

ค่าคำนวณทั้งชุดของแต่ละขั้นถูก **คัดลอกตอนกดเริ่ม** และบันทึกไปกับผล
การแก้หน้าตั้งค่าระหว่างรันไม่มีผลกับการทดสอบที่กำลังเดิน

## 2. การแปลงน้ำหนักเป็น flow และค่าแก้

```
Q₀ = Δw / Δt × 3600                     [ml/h]  flow "ก่อนแก้" (ถือ 1 g = 1 ml แบบ ARGOS)
Q  = (Q₀ − B) × Z                       [ml/h]  flow "สุทธิ" — ใช้ตัดสิน PASS/FAIL
Z  = 1 / (ρw − ρa) × (1 − ρa / ρb)      [ml/g]  ISO 4787:2021 (เหมือน ISO 8655-6)
E  = (Q − Q_target) / Q_target × 100    [%]     (E₀ คิดแบบเดียวกันจาก Q₀)
```

| สัญลักษณ์ | ความหมาย | ที่มา |
|---|---|---|
| `ρw` | ความหนาแน่นน้ำ (g/ml) | **อุณหภูมิของเหลว** ในฟอร์ม (0–40 °C) → สูตร Tanaka et al. (2001) ที่ CIPM แนะนำ · ไม่กรอก/นอกช่วง: ค่าในหน้าตั้งค่า (0.9982) |
| `ρa` | ความหนาแน่นอากาศ (g/ml) | OIML R111-1 E.3: `ρa[kg/m³] = (0.34848 p − 0.009 hr e^(0.061 t)) / (273.15 + t)` |
| `t` | อุณหภูมิอากาศ (°C) | ฟอร์ม "อุณหภูมิอากาศ" · ว่าง = ใช้อุณหภูมิของเหลว · ไม่มีทั้งคู่ = 20 °C |
| `hr` | ความชื้นสัมพัทธ์ (%RH) | ฟอร์ม "ความชื้น" (0–100) · ว่าง = ค่าตั้ง (50) |
| `p` | ความดันอากาศ (hPa) | ฟอร์ม "ความดันอากาศ" (500–1200) · ว่าง = ค่าตั้ง (1013.25) |
| `ρb` | ความหนาแน่นตุ้มน้ำหนักที่สอบเทียบตราชั่ง | ค่าตั้ง (8.0 g/ml = เหล็กกล้า OIML R111) |
| `B` | อัตราน้ำหนักพื้นฐาน (g/h) | จาก self-check ที่ **ผ่าน** ของวันนั้น (หัวข้อ 8) · ถ้าไม่มี: 0 |

ตัวอย่าง (50 %RH, 1013.25 hPa, อุณหภูมิอากาศ = ของเหลว) — ตรงกับตาราง Z ใน ISO 4787 / ISO 8655-6:

| °C | ρw (g/ml) | ρa (kg/m³) | Z (ml/g) | Z × ρw − 1 (ผลของแรงลอยตัว) |
|---|---|---|---|---|
| 20 | 0.99821 | 1.1993 | 1.00285 | +0.105 % |
| 22 | 0.99777 | 1.1905 | 1.00328 | +0.105 % |
| 25 | 0.99705 | 1.1774 | 1.00400 | +0.103 % |
| 28 | 0.99624 | 1.1643 | 1.00481 | +0.102 % |
| 30 | 0.99565 | 1.1555 | 1.00539 | +0.102 % |

- **อุณหภูมิของเหลวมีผลมากที่สุด** (20 → 30 °C ต่างกัน 0.25 %) · ความชื้น 0 → 100 %RH เปลี่ยน Z แค่ 0.001 %,
  ความดัน 990 → 1030 hPa เปลี่ยน 0.004 % — ไม่กรอกก็แทบไม่มีผล แต่โปรแกรมบันทึกว่าใช้ค่าจากไหน
- ปิดการแก้แรงลอยตัวได้ในหน้าตั้งค่า → `Z = 1/ρw` (แบบก่อนเวอร์ชันนี้)
- ไม่ได้ใช้ค่าแก้ "น้ำที่มีอากาศละลาย" ของ Tanaka (−2 ถึง −5 ppm = ≤ 0.0005 %) และค่าขยายตัวของภาชนะ
  (เทอม γ ของ ISO 4787 ใช้กับเครื่องแก้ว — ปั๊มวัดปริมาตรที่ส่งออก ณ อุณหภูมิของเหลว)
- นอกช่วงที่สูตรอากาศรับรอง (10–30 °C, 900–1100 hPa, < 80 %RH) ยังคำนวณ แต่บันทึกคำเตือนไว้กับผล
- `B` เป็นค่าลบเมื่อมีการระเหย (น้ำหนักหาย) การหักค่าลบทำให้ flow ที่แก้แล้วสูงขึ้น
- flow ที่คำนวณได้ติดลบจะถูกปัดเป็น 0
- **ยังไม่มี:** งบความไม่แน่นอนของการวัด

- กราฟ flow รายช่วง: เส้นประจาง "ก่อนแก้" = ค่าเฉลี่ยสะสมของ Q₀ (กดชื่อบนหัวกราฟเพื่อซ่อน, จำไว้ใน settings)
- รายละเอียดผลย้อนหลัง: การ์ด "ค่าแก้ g → ml (สอบย้อนหลัง)" แสดงทุกค่า + ที่มา + แถว **ตรวจสูตร** `(Q₀ − B) × Z` ✓

- หน้าประวัติมีคอลัมน์ "ก่อนแก้ (%)" · Excel มีคอลัมน์ อุณหภูมิอากาศ ความดัน ρa Z flow/error ก่อนแก้

## 3. Slope (flow ขณะนั้น)

เส้นตรง least-squares ผ่าน N จุดล่าสุด แล้วแปลงด้วยสูตรในหัวข้อ 2

```
slope = (N·Σtw − Σt·Σw) / (N·Σt² − (Σt)²)      [g/s]
```

- จำกัดค่าสูงสุดไว้ที่ 5 × rate ที่ตั้ง แสดงเมื่อมีอย่างน้อย 10 จุด
- **แสดงผลทุกวิธีจับ** (ให้เห็นรูปแบบการไหล) แต่ **ใช้คำนวณ** เฉพาะวิธีจับรอบปั๊ม
- N มาจากไหน: ดูหัวข้อ 9

ไฟล์: `core/stats.py` (`regression_slope`), `core/engine.py` (`_SlopeWindow`)

## 4. วิธีจับ (แบ่งช่วงวัด)

flow ของ 1 ช่วงวัดทุกวิธีใช้สูตรในหัวข้อ 2 กับจุดต้น–ปลายของช่วง ต่างกันที่จุดต้น–ปลายมาจากไหน

### 4.1 จับรอบปั๊ม (peak-to-peak) — `pump_cycle`

**เริ่มทำงานเมื่อ** หน้าต่าง slope เต็ม N จุดแล้ว

**หาจุดกลับตัว** เก็บ slope ไว้ในหน้าต่างกว้าง `2·n_bar + 1` จุด
- จุดกึ่งกลางเป็นค่าสูงสุดของหน้าต่าง → **TOP** · เป็นค่าต่ำสุด → **DOWN** · ค่าเท่ากันหมด → ไม่นับ
- จึงรู้ผลช้ากว่าเหตุการณ์จริง n_bar จุด

**กฎการสลับ** TOP กับ DOWN ต้องสลับกันเสมอ ถ้าเจอชนิดเดิมซ้ำ จะไม่รายงาน
แต่เลื่อนจุดอ้างอิงไปยังตัวที่ดีกว่า (TOP เลือก slope สูงกว่า, DOWN เลือก slope ต่ำกว่า)

**1 รอบปั๊ม** = จุดกลับตัวชนิดเดียวกัน 2 จุดติดกัน จึงมี 2 สายซ้อนกัน (สาย A และ B เหลื่อมกันครึ่งรอบ)

**จับรอบคู่ / จับรอบเดียว** (ตั้งค่า → การคำนวณ → การจับรอบปั๊ม, `EngineSettings.cycle_chains`)
- จับรอบคู่ (2, ค่าเริ่มต้น): ใช้ทั้งสาย A และ B — ได้ช่วงวัดเป็น 2 เท่า, ค่ารวม = ค่าเฉลี่ยของ 2 สาย
- จับรอบเดียว (1): ใช้เฉพาะสาย A (ชนิดจุดกลับตัวที่เจอก่อน) — รอบของอีกชนิดถูกข้าม ไม่เป็นช่วงวัด
  ค่ารวม = สาย A, จบเมื่อสาย A ครบเวลา/ครบจำนวนรอบ
- ค่าที่ใช้ตัดสินเหมือนกัน (ค่าเฉลี่ยของช่วงวัดที่ครบ) — ค่าที่ใช้จริงบันทึกไปกับผลใน `engine_settings.cycle_chains`

**เงื่อนไขจบ**
- ตามเวลา: เวลาจากจุดเริ่มของสายถึงปลายรอบล่าสุด ≥ เวลาที่ตั้ง ทั้งสองสาย (ตรวจที่ปลายรอบ จึงไม่ตัดกลางรอบ)
- ตามจำนวนรอบ: แต่ละสายครบ N รอบ ทั้งสองสาย (ตั้ง 30 รอบ = 60 ช่วงวัด; จับรอบเดียว = 30 ช่วงวัด)

ไฟล์: `core/cycle_analyzer.py`, `core/strategies/pump_cycle.py`

### 4.2 จับตามเวลา แบ่งเป็นช่วง — `time_interval`

จุดเริ่ม = จุดแรกหลังทิ้งข้อมูลช่วงแรก · ตัดช่วงทุก L วินาที (เลือกได้เฉพาะค่าที่หารเวลาทดสอบลงตัว)
· จบเมื่อครบ `เวลาทดสอบ / L` ช่วง · กราฟ slope ยังแสดงอยู่ แต่ไม่มีจุด peak/valley

### 4.3 จับตามเวลา วัดรวดเดียว — `time_total`

เหมือน 4.2 แต่ L = เวลาทดสอบทั้งหมด ได้ช่วงวัดเดียว (จึงไม่มี CI และ SD)

ไฟล์: `core/strategies/time_based.py`

## 5. สถิติของช่วงวัด

คิดจาก **ทุกช่วงวัด** ตั้งแต่เริ่มการทดสอบ (n = จำนวนช่วง, s = ส่วนเบี่ยงเบนมาตรฐานตัวอย่าง)

| ค่า | สูตร | แสดงเป็น |
|---|---|---|
| Flow เฉลี่ย | `Q̄ = ΣQ / n` | ml/h |
| CI 95 % | `t(0.975, n−1) · s / √n` | **ไม่แสดง** (ผู้ใช้สั่งเอาออก 2026-11-12 — ช่วงวัดติดกันไม่เป็นอิสระต่อกัน CI จึงแคบเกินจริง) ยังคำนวณและบันทึกใน summary |
| 2 SD | `2 · s` | ± % ของ rate ที่ตั้ง |

ค่าเดียวกันนี้คิดกับระยะเวลาของแต่ละช่วงด้วย แสดงเป็นวินาที (การ์ดเวลาต่อรอบปั๊ม)

**เส้นบนกราฟ flow รายช่วง** (แสดงผลอย่างเดียว ไม่ใช้ตัดสิน — กดชื่อเส้นบนหัวกราฟเพื่อซ่อน/แสดง)
- Moving avg (ค่าเริ่มต้น): ค่าเฉลี่ยสะสม **ตั้งแต่ช่วงแรกถึงช่วงที่ k** (start → end) `M_k = (Q_1 + … + Q_k) / k`
  รวมทุกสายตามลำดับที่จบ วาดเป็นจุดต่อจุดที่เวลาปลายช่วง k · จุดสุดท้าย = `Q̄` (ค่าที่ใช้ตัดสิน) พอดี
  (เดิม 2026-11-12 เช้าเป็นค่าเฉลี่ย 6 ช่วงล่าสุด — ผู้ใช้ขอเปลี่ยนเป็นแบบสะสมตั้งแต่ต้น)
- ค่าเฉลี่ยรวม: เส้นแนวนอนที่ `Q̄` ของทุกช่วงตั้งแต่เริ่ม
- รูปแบบ: ขั้นบันได (ช่วงวัดเป็นเส้นแนวนอนจากต้นถึงปลายช่วง) หรือ จุดต่อเส้น (1 จุดที่เวลาปลายช่วง)

**วิธีคำนวณ (2026-11-13):** สะสมแบบ Welford (`core.stats.RunningStats`) — ค่าใหม่ 1 ค่าใช้งานคงที่
ไม่คำนวณใหม่จากทุกช่วงทุกครั้ง (เดิมงานรวมโตแบบ n² — รันหลายชั่วโมงที่ rate สูงมีหลายหมื่นช่วง) ผลเท่ากับ numpy (ddof = 1)
ค่า t ของ CI ใช้ n ไม่เกิน 1001 (ต่างจากค่าจริง < 0.1 % และ CI ไม่แสดงบนจอ)

ไฟล์: `core/stats.py` (`RunningStats`), `core/engine.py` (`_compute_stats`)

## 6. การตัดสิน PASS / FAIL

```
E = (Q̄ − Q_target) / Q_target × 100         PASS เมื่อ |E| ≤ เกณฑ์ยอมรับ
```

- `Q̄` = ค่าเฉลี่ยของช่วงวัดที่ **ครบสมบูรณ์** เท่านั้น (ถ้ายังไม่มีเลย ใช้ค่าเฉลี่ยสะสมแทน)
- ถ้าการทดสอบถูกหยุดก่อนครบ ผลติดป้ายว่า "ไม่ครบ"
- **ค่าเฉลี่ยสะสม (สด)** บนการ์ดกลาง = flow จากจุดเริ่มของสายถึงตอนนี้ แกว่งตามจังหวะรอบปั๊ม จึง **ไม่ใช้ตัดสิน**

## 7. ช่วงก่อนวัด (pre-run)

ข้อมูลช่วงนี้บันทึกแยกใน `prerun.csv` และไม่เข้าการคำนวณผล เมื่อเข้าช่วงวัดจริงทุกอย่างเริ่มนับใหม่

### 7.1 เงื่อนไขเข้าช่วงวัดจริง

| โหมดเริ่มวัด | เข้าเมื่อ |
|---|---|
| ทันที | จุดแรก (ไม่มี pre-run เว้นแต่ต้องวัดคาบรอบปั๊มก่อน) |
| หลังปล่อยรันตามเวลา | เวลาผ่านไป ≥ ค่าที่ตั้ง |
| อัตโนมัติเมื่อ flow นิ่ง | ผ่านเกณฑ์ในหัวข้อ 7.3 |
| กดปุ่มเอง | ผู้ใช้กด "เริ่มวัดเดี๋ยวนี้" |

ทุกโหมดกด "เริ่มวัดเดี๋ยวนี้" เพื่อข้ามได้

### 7.2 การวัดคาบรอบปั๊ม

ใช้เมื่อวิธีจับ = จับรอบปั๊ม และยังไม่มีค่าคาบจากโปรไฟล์ (หรือผู้ใช้เลือก "วัดก่อนเริ่มทุก rate")

1. นำน้ำหนักช่วง pre-run มาลบเส้นตรงแนวโน้ม เหลือเฉพาะส่วนที่แกว่งตามรอบปั๊ม
2. คำนวณ autocorrelation ของส่วนที่เหลือ
3. คาบ P = ระยะเลื่อนที่ autocorrelation ขึ้นยอดครั้งแรกหลังผ่านศูนย์
4. ยอมรับ P เมื่อครบทุกข้อ
   - มีข้อมูล ≥ 30 s และยาว ≥ 3 เท่าของ P
   - ค่าสหสัมพันธ์ที่ยอด ≥ 0.5
   - ขนาดการแกว่ง ≥ 3 เท่าของความละเอียดตราชั่ง (ความละเอียด = ผลต่างอันดับ **สอง** ที่เล็กที่สุดที่ไม่ใช่ 0)
   - ประเมิน 2 ครั้งติดกัน (ห่างกัน 5 s) ได้ค่าต่างกันไม่เกิน 5 %
5. ถ้าหาไม่ได้ภายใน 300 s → ใช้คาบจากโปรไฟล์ (ถ้ามี) ไม่งั้นเดาจากปริมาตรต่อรอบเริ่มต้น และบันทึกหมายเหตุไว้ในผล
   (เดิมใช้ขนาดหน้าต่างกำหนดเอง 250 จุด — ยกเลิก 2026-11-13)

**แก้บั๊ก 2026-11-13 (ความละเอียดตราชั่ง):** เดิมใช้ผลต่างอันดับหนึ่งที่เล็กที่สุด ซึ่งที่ rate สูงคือ "flow ต่อจุด"
(200 ml/h ที่ 5 Hz ≈ 11 mg ต่อจุด) ไม่ใช่ความละเอียด → ปฏิเสธการแกว่งจริงทั้งหมด (ตราชั่งจำลอง 200 ml/h หาคาบไม่ได้เลย)
ผลต่างอันดับสองตัดส่วน flow คงที่ออก · ตรวจกับข้อมูลจริงแล้วได้เท่าเดิม: TE-171 50 ml/h 14.35 s, 200 ml/h 3.51 s,
session id 11 2.131 s (10 ml/h ยังได้ 357 s ผิดเหมือนเดิม — ข้อจำกัดที่รู้)

ผลกับสัญญาณจำลองคาบ 8–150 s: คลาดไม่เกิน 1 %

### 7.3 การตรวจ flow นิ่ง (โหมดเริ่มอัตโนมัติ)

แบ่งข้อมูลล่าสุดเป็น K ช่วงติดกัน ช่วงละ T วินาที แล้วดูน้ำหนักที่เพิ่มในแต่ละช่วง
**K, T และเกณฑ์อื่นแยก 3 กลุ่ม ตามชนิดเครื่อง × วิธีจับ** (syringe จับรอบปั๊มไม่ได้ · infusion บางครั้งจับตามเวลา)
และแต่ละ **ยี่ห้อ + รุ่น + ชนิด + ชุดสาย/syringe** ตั้งค่าเฉพาะได้ (wizard ขั้น 4 → "ปรับสำหรับรุ่นนี้…")

| กลุ่ม (ค่าเริ่มต้น — ข้อเสนอของ AI) | ความยาวช่วง T | K | ยืดให้ได้น้ำหนักต่อช่วง ≥ | รอนานสุด |
|---|---|---|---|---|
| Infusion · จับรอบปั๊ม | 1 คาบรอบปั๊ม (ยังไม่รู้คาบ: 15 s) | 3 | — | 15 นาที |
| Infusion · จับตามเวลา | 15 s ปัดขึ้นเป็นจำนวนเต็มรอบปั๊ม (ถ้ารู้คาบ) | 3 | 20 mg | 15 นาที |
| Syringe · จับตามเวลา | 30 s | 4 | 20 mg (1 ml/h → 72 s) | 20 นาที |

- คาบ: วัดได้ในช่วงก่อนวัด (ถ้ามี) มาก่อน ไม่งั้นจากโปรไฟล์ของรุ่น (`EngineSettings.expected_period_s`)
- **รอนานสุด:** ครบแล้วเริ่มวัดเลย และบันทึก `stability_confirmed = false` + หมายเหตุในผล (กดเริ่มเองก่อนนิ่งก็บันทึกเหมือนกัน)
  wizard เตือนล่วงหน้าเมื่อ K × T ของ rate ใดยาวเกินเวลารอ (rate นั้นจะยืนยันว่านิ่งไม่ได้เลย)
- **แก้บั๊ก:** เดิมเก็บข้อมูลช่วงก่อนวัดได้แค่ 900 s — ถ้า K × T เกิน (คาบ > 225 s ≈ ต่ำกว่า 4 ml/h) ไม่มีวันนิ่ง
  ตอนนี้ขยายเป็น `max(900, 1.2 × K × T + 60)` s
- ผลกับข้อมูลจริง TE-171 (เริ่มอัตโนมัติ, เวลาที่นิ่ง): 200 ml/h เดิมไม่นิ่งเลยใน 7 นาที → 14 s (รู้คาบ) ·
  50 ml/h 62 → 42 s · 10 ml/h 308 → 287 s · Infusion จับตามเวลา 54 / 89 / 287 s
- ผลบันทึก `stable_after_s` (นิ่งหลังเริ่มกี่วินาที) และ `engine_settings.stability_source` (เช่น `model:syringe_time`)

| ค่า | สูตร |
|---|---|
| ความแกว่ง V | `(มากสุด − น้อยสุด) / ค่าเฉลี่ย × 100` |
| แนวโน้ม D | `|ค่าเฉลี่ยครึ่งหลัง − ค่าเฉลี่ยครึ่งแรก| / ค่าเฉลี่ย × 100` |
| เกณฑ์ L | `เกณฑ์พื้นฐาน (2 %) + 2 × ความละเอียดตราชั่ง / น้ำหนักที่เพิ่มต่อช่วง × 100` |

**นิ่ง เมื่อ `V ≤ L` และ `D ≤ L / 3`**

- ส่วนที่บวกเข้าเกณฑ์ คือความแกว่งที่มาจากการปัดเศษของตราชั่งล้วนๆ
  (ที่ 10 ml/h บนตราชั่งละเอียด 1 mg ช่วง 15 s เพิ่มเพียง 41 mg การปัดเศษอย่างเดียวทำให้ดูแกว่งเกิน 2 %)
- เงื่อนไขแนวโน้มกัน flow ที่ไหลขึ้น/ลงช้าๆ แต่แต่ละช่วงยังดูใกล้กัน
- ความละเอียดตราชั่งประเมินจากขั้นเล็กที่สุดที่เห็นในข้อมูล

**สถานะตามหลักการ:** เป็นกฎเชิงปฏิบัติที่อธิบายได้ ไม่ใช่การทดสอบทางสถิติเต็มรูป
เท่าที่ทราบ IEC 60601-2-24 ใช้วิธีกำหนดช่วงเวลาให้เครื่องเดินก่อนวิเคราะห์ ไม่ได้ใช้การตรวจนิ่ง
ถ้าต้องอ้างมาตรฐาน ให้ใช้โหมด "หลังปล่อยรันตามเวลา" (ควรเปิดมาตรฐานยืนยันก่อนใช้อ้างอิง)

## 8. Self-check (การระเหย + การไหลของค่าตราชั่ง)

**ทำอย่างไร** จัดบีกเกอร์เหมือนตอนทดสอบจริง หยุดปั๊ม บันทึกน้ำหนักตามเวลาที่ตั้ง (10 นาที)

**คำนวณ** (ทิ้ง 2 s แรก)

| ค่า | สูตร |
|---|---|
| อัตราพื้นฐาน B | ความชันของเส้นตรง least-squares ของน้ำหนักเทียบเวลา (g/h) |
| ความคลาดเคลื่อนมาตรฐานของ B | ค่าที่มากกว่าระหว่าง `SD ของส่วนเหลือ / √Σ(t − t̄)²` กับ `SD(b_i) / √k` (ช่วงย่อย) |
| อัตราช่วงย่อย b_i | แบ่งเวลาเป็น k = 10 ช่วงเท่ากัน (≥ 6 จุด/ช่วง ไม่งั้นลด k ทีละ 2 จนเหลือ 4) ความชันของแต่ละช่วง |
| noise ของตราชั่ง | SD ของส่วนเหลือรอบเส้นตรง |

B รวมการระเหยและการไหลของค่าตราชั่งไว้ด้วยกัน (แยกไม่ได้และไม่จำเป็น เพราะหักรวมกัน)

**ผ่านเมื่อครบทุกข้อ** (เป็นข้อเสนอ ปรับได้ในหน้าตั้งค่า)
- บันทึกครบเวลาที่ตั้ง
- นิ่งแล้ว: **ไม่** เป็นจริงทั้งสองข้อพร้อมกัน
  `D = |mean(b ครึ่งแรก) − mean(b ครึ่งหลัง)| > 30 mg/h` และ `z = D / √(s₁²/n₁ + s₂²/n₂) > 3`
  (s = SD ของอัตราช่วงย่อยในแต่ละครึ่ง, n = จำนวนช่วงย่อย) — คือความต่างต้องเกินทั้งค่าที่มีผลจริง และเกินที่ noise อธิบายได้
  ทำไม: ค่าตราชั่งจริงไหลขึ้นลงช้าๆ ต่อเนื่อง (จุดติดกันสัมพันธ์กัน 0.999) SE จากสูตรเส้นตรงปกติจึงเล็กเกินจริง
  ~25 เท่า (ไฟล์จริง 2026-11-12: 6 mg/h เทียบ 167 mg/h จากช่วงย่อย) เกณฑ์ตายตัวเดิม 30 mg/h จึงไม่ผ่านแทบทุกครั้ง
  (self-check จริง 2 ครั้ง: ต่างกัน 111 และ 869 mg/h — ครั้งหลังน้ำหนักเพิ่มในครึ่งหลังจริง z = 4.95 ยังไม่ผ่านตามควร)
- |B| ≤ 500 mg/h (มากกว่านี้ไม่น่าใช่การระเหย)

**การใช้** ผลที่ผ่านใช้เป็น B ในหัวข้อ 2 กับทุกการทดสอบของ **วันเดียวกัน** โดยอัตโนมัติ
ใช้ผลครั้งล่าสุดของวัน ถ้าครั้งล่าสุดไม่ผ่านจะไม่ใช้ค่าแก้ · self-check ที่ถูกยกเลิกไม่ถูกบันทึก

**ข้อจำกัดที่รู้:** ถ้าการระเหยน้อยและตราชั่งละเอียด 1 mg เวลา 10 นาทีจะหยาบเกินไป ควรตั้งให้นานขึ้น
ข้อมูลดิบของ self-check ยังไม่ถูกบันทึกเป็นไฟล์ (มีแค่ผลสรุปในฐานข้อมูล)

## 9. ขนาดหน้าต่างคำนวณ และโปรไฟล์ปั๊ม (เฉพาะวิธีจับรอบปั๊ม)

หน้าต่าง slope (N) และ n_bar ต้องพอดีกับคาบรอบปั๊ม: `N = คาบ × r / ช่วงเวลาต่อจุด`, `n̄ = คาบ × h / ช่วงเวลาต่อจุด`
(r, h = 0.4 หรือค่าของ rate นั้น 9.2/9.4) — สูตรเดียวทุกที่: `core/windows.py` (`cycle_windows`)

### 9.0 ขั้นต่ำและจุดต่อรอบ (ข้อ จ, ง — 2026-11-13)

```
จุดต่อรอบ  ppc = คาบ / ช่วงเวลาต่อจุด
N  = max(5, round(ppc × r))        n̄ = max(3, round(ppc × h))
```
- **เดิม (บั๊ก):** ได้ < 5 จุด → ถอยไปใช้ค่าในหน้าตั้งค่า 250/250 **เงียบๆ** · ขั้นต่ำ 10 จุดตายตัว และหน้าต่าง < 10 จุดทำให้ crash
  (slope = None เข้าตัวจับ peak) — ตอนนี้รู้คาบ = คำนวณจากคาบเสมอ ไม่มีค่าตายตัวอีก
- ขั้นต่ำ 5 / 3 มาจากการเล่นซ้ำ session id 11 (ppc 10.6): 5–10 / 3–5 จุด จับคาบได้ถูก (0.99 × คาบ, CV เวลาต่อรอบ 0.05)
  · 4 / 2 แกว่ง (CV 0.12) · 3 / 2 จับผิด (0.85 × คาบ)
- ppc < 12 → **เตือน** (wizard, แผงแผน, log) · ppc < 8 → ไม่ให้เริ่มแบบจับรอบปั๊ม — เสนอ "จับตามเวลา ช่วง = จำนวนเต็มรอบ ≥ 30 s"
  หรือเพิ่มความถี่ตราชั่ง (9600 baud / stream — ตั้งที่ตัวตราชั่ง) · เกณฑ์ 8/12 อิงข้อมูลจุดเดียว ยังไม่ยืนยันกับรุ่นอื่น
- ที่ ppc ต่ำ จับรอบได้ถูกแต่ผลรายรอบแกว่งมาก: session id 11 จับ peak ±2SD 7–9 % · จับตามเวลา 14 × คาบ (29 s) ±2SD 2.4 %
  ค่าเฉลี่ยเท่ากัน (201.9 ml/h)
- ช่วงสัดส่วน (ข้อ ง): แนะนำ 0.3–0.5 × คาบ (นอกนี้เตือน — ยกเว้นค่าที่ปรับจากข้อมูลจริง) · ยอมรับ 0.1–0.75 (นอกนี้ไม่ให้บันทึก/เริ่ม)
- บันทึกในผล: `points_per_cycle`, `sample_period_s` (ค่ากลางของช่วงวัด)

**หลักการ peak ซ้าย/ขวา:** หน้าต่าง slope ลากเส้นตรงผ่านน้ำหนัก N จุดล่าสุด = flow ขณะนั้น (แกว่งตามรอบปั๊ม)
แล้วตัวจับดู slope ทีละ `2 × n_bar + 1` จุด — จุดกลางสูง/ต่ำสุด = peak/valley, 1 รอบ = peak → peak
- f ต้อง **< 0.5**: หน้าต่างยาวถึง 1 คาบ การแกว่งเฉลี่ยหายหมด, n_bar ≥ ครึ่งคาบ ข้าม peak
- f ต้อง **ไม่เล็กเกิน**: ข้อมูลจริง TE-171 — f < 0.3 จับได้ "ครึ่งรอบ" (ปั๊มมี 2 จังหวะต่อรอบ) เวลาต่อรอบ = 0.53 × คาบ
- คาบแปรผกผันกับ rate (ปริมาตรต่อรอบคงที่) จำนวนจุดจึงต่างกันทุก rate
  (5.1 Hz, TE-171: 200 ml/h ~7 จุด, 50 ml/h ~29 จุด, 10 ml/h ~146 จุด)

**คาบมาจากไหน** (เลือกใน wizard ช่อง "ขนาดหน้าต่างคำนวณ")

| ตัวเลือก | พฤติกรรม |
|---|---|
| จากโปรไฟล์ปั๊ม (ค่าเริ่มต้น) | มีโปรไฟล์ + รู้ความถี่ตราชั่ง: ใช้ทันที ไม่ต้องรอ · ไม่งั้นวัดคาบก่อนเริ่ม |
| วัดก่อนเริ่มทุก rate | วัดใหม่ทุกครั้ง (ถือเป็นการสอบเทียบ: ผลปรับหน้าต่างทับค่าที่แก้เองได้) |
| Calibration รอบปั๊มใหม่ | 9.3 |

ตัวเลือก "กำหนดเอง (ค่าในหน้าตั้งค่า, ค่าเดียวทุก rate)" **ถูกเอาออก** (แผนเก่าที่ตั้งไว้ = จากโปรไฟล์) · ค่า regression ในหน้าตั้งค่า
เหลือความหมายเดียว: ความเรียบของกราฟ slope ของวิธีจับตามเวลา · ค่า n̄ ในหน้าตั้งค่าเอาออก
ระหว่างวัดคาบก่อนเริ่ม กราฟใช้หน้าต่างจากคาบที่เดา (ไม่ใช่ 250) · `services/window_plan.py` (`rate_window`) คือจุดเดียวที่
wizard, แผงแผนทดสอบ, controller และหน้าข้อมูลสอบเทียบใช้คำนวณค่าราย rate — ทุกจอเห็นค่าเดียวกัน

**โปรไฟล์ปั๊ม** = สิ่งที่จำไว้ต่อ ยี่ห้อ + รุ่น + **ชนิดเครื่อง** + ชุดสาย/syringe (`core.profiles.pump_key`)
— ใช้กุญแจเดียวกันกับหน้าต่างที่ปรับแล้ว (9.2) และเกณฑ์ช่วงก่อนวัด (7.3) · ฐานข้อมูลเก่าย้ายให้อัตโนมัติ (สำรองไฟล์ก่อน)

- สมมติฐาน: ปั๊มแบบ finger ส่งของเหลวต่อรอบเกือบคงที่
  `ปริมาตรต่อรอบ (ml) = flow × คาบ / 3600` → `คาบ ณ rate ใดๆ = ปริมาตรต่อรอบ × 3600 / rate`
- ทุกการทดสอบแบบจับรอบปั๊มที่ **เก็บผล** (ครบเวลา, ≥ 4 ช่วงวัด) เพิ่มข้อสังเกต 1 รายการ: (rate, คาบที่วัดได้)
- การหาคาบสำหรับ rate ที่จะทดสอบ
  1. เคยวัดที่ rate นี้ (± 2 %) → ใช้ค่าเฉลี่ยของที่เคยวัดจริง
  2. ไม่เคย → คำนวณจากปริมาตรต่อรอบ
  3. รุ่นยังไม่เคยวัด แต่ผู้ใช้กำหนด "ค่าเริ่มต้นของรุ่น" ไว้ → คำนวณจากค่านั้น (window_source = model_default)
  4. ไม่มีอะไรเลย → วัดก่อนเริ่ม (7.2) · หาไม่ได้ภายในเวลาที่ตั้ง → เดาจาก "ปริมาตรต่อรอบเริ่มต้น" ในหน้าตั้งค่า
     (0.16 ml, window_source = default) — เดิมใช้ 250 จุดตายตัว ซึ่งยาวกว่า 1 คาบที่ 200 ml/h
- การกันข้อมูลเสีย
  - คาบต่างจากที่เคยวัดที่ rate เดียวกันเกิน 25 % → ไม่จำ (น่าจะจับรอบพลาด)
  - ปริมาตรต่อรอบต่างจากโปรไฟล์เกิน 25 % → จำไว้ใช้ **เฉพาะ rate นั้น** ไม่รวมเข้าโปรไฟล์

**สถานะ:** สมมติฐานปริมาตรต่อรอบคงที่ยืนยันแล้วกับ TE-171 + TI*PU200L (0.184–0.189 ml ที่ 10/50/200 ml/h)
ปั๊มจริงของผู้ใช้: TE-112 + TI*PU200L 0.199, LF-600 0.211, TE-112 + ME 20 drops 0.118 ml — **ต่างกันมากตามชุดสาย**

### 9.1 popup เตือนสอบเทียบก่อนสร้างการทดสอบ (`ui/dialogs/calibration_prompt.py`) — 2026-11-13 แทน popup รุ่นใหม่เดิม

ขึ้นเมื่อวิธีวัด **ใช้รอบปั๊ม** และ ยี่ห้อ + รุ่น + ชนิด + Set IV นี้ยังไม่ได้สอบเทียบ (ไม่มีค่า tuned) ที่ rate ใดในแผน
หรือมี rate ที่ ppc < 12 / ค่านอกช่วง — **วิธีจับตามเวลาไม่ถามเลย** (syringe ค่าเริ่มต้นจับตามเวลา)
ใช้ได้ทุกโหมด (Calibration / Inspection / Quick Test) · ทุกครั้งที่สร้างการทดสอบ ถ้ายังไม่สอบเทียบ ก็ยังเตือน

| ปุ่ม | ผล |
|---|---|
| **สอบเทียบเลย** (แนะนำ, ติ๊กเรียง rate สูง → ต่ำ ได้) | วัดคาบก่อนทุก rate (รุ่นใหม่ = จากโปรไฟล์ ซึ่งวัดเองอยู่แล้ว) แล้วปรับหน้าต่างจากผลที่เก็บ → tuned |
| ข้ามการสอบเทียบ… | ตารางค่าราย rate (ค่าเริ่มต้น หรือค่าที่เคยบันทึกไว้ให้รุ่นนี้) แก้เป็นจำนวนจุดได้ · รุ่นที่ไม่รู้ปริมาตรต่อรอบมีช่องกรอก |
| → ใช้กับการทดสอบนี้เท่านั้น | ค่าที่แก้/ค่าที่ยังไม่สอบเทียบ เก็บในแผน (`StepConfig.regression_fraction/half_fraction`, ที่มา = plan) |
| → บันทึกให้รุ่นนี้แล้วใช้ | เก็บ `window_tuning.source = uncalibrated` (+ ปริมาตรต่อรอบเป็นค่าแทนของรุ่น) — ครั้งหน้ายังเตือน แต่ข้ามแล้วใช้ค่านี้ |
| เปลี่ยนเป็นจับตามเวลา (เมื่อ ppc < 12) | วิธีจับ = time_interval ช่วงละ `ceil(30 / คาบ) × คาบ` |

ค่าเริ่มต้นควรใกล้ค่าจริง: ช่วง f ที่ใช้ได้แคบ (~0.33–0.48 × คาบจริงของ TE-171) ถ้าค่าที่เดาคลาดเกิน ~±20 % จะจับครึ่งรอบหรือข้ามรอบ

### 9.2 ปรับขนาดหน้าต่างจากข้อมูลย้อนหลัง (`core/tuning.py`) — แยก 2 หน้าต่าง แยกราย rate

หน้าต่าง regression (N = คาบ × r) และ n̄ ของตัวจับ peak (n̄ = คาบ × h) **ปรับแยกกัน** และ
**แต่ละ ยี่ห้อ + รุ่น + ชนิด + ชุดสาย + rate มีค่าของตัวเอง** (ไม่ใช้ค่าเดียวทุก rate)
เล่น raw ของการทดสอบที่เก็บไว้ผ่าน `FlowEngine` ตัวจริงซ้ำ ค้นทีละแกน: r = h ทุกค่า (0.15 … 0.45) → คง r ลอง h → คง h ลอง r
(~19 คู่ แทน 49 คู่) แล้วให้คะแนน

```
คะแนน = CV(เวลาต่อรอบ) + CV(flow ต่อรอบ) + |เวลาต่อรอบเฉลี่ย / คาบอ้างอิง − 1|      (ยิ่งน้อยยิ่งดี)
```
- คาบอ้างอิงไม่ขึ้นกับ f: โปรไฟล์ ตรวจไขว้กับ autocorrelation ของทั้งไฟล์ (ถ้า autocorrelation ≈ 2 × โปรไฟล์
  = โปรไฟล์น่าจะเรียนรู้ครึ่งรอบมา ใช้ autocorrelation แทน)
- เปลี่ยนจากค่าปัจจุบันเมื่อคะแนนดีขึ้น ≥ 10 % เท่านั้น · ใช้ข้อมูลล่าสุด ≤ 5 การทดสอบต่อ rate (เฉพาะที่ "ครบ")
- เก็บต่อ ยี่ห้อ + รุ่น + ชนิด + ชุดสาย + rate (ตาราง `window_tuning`: r, h, จำนวนจุดจริง, ช่วงเวลาต่อจุด, คะแนน, **ที่มา**)
- rate ที่ยังไม่มีค่า: อยู่ระหว่าง 2 rate ที่ **สอบเทียบแล้ว** = เทียบสัดส่วนบนสเกล log ของ rate · นอกช่วง = ค่าตั้ง
  (`Repository.window_fractions` คืนที่มา tuned / manual / uncalibrated / interpolated / default — บันทึกใน `engine_settings.window_fit`)
- ผลปรับอัตโนมัติไม่ทับค่าที่ผู้ใช้แก้เอง (manual) เว้นแต่แผน Calibration / วัดคาบก่อนทุก rate · ทับค่า uncalibrated เสมอ
- ทำงาน: อัตโนมัติหลังกด "เก็บ" (thread เบื้องหลัง ยกเลิกเองเมื่อเริ่มการทดสอบใหม่) และปุ่ม "ปรับหน้าต่างจับ peak" ในหน้าประวัติ
- ผลกับข้อมูลจริง TE-171 (capture 2026-11-12, ค้น 2 แกน): 200 ml/h → 0.40/0.40 = 10/7 จุด (ดีสุด 0.45/0.45 ต่างไม่ถึง 10 %)
  · 50 ml/h → 0.40/0.40 = 27/27 จุด (ดีสุด r 0.45 h 0.30 ต่างไม่ถึง 10 %) · 10 ml/h → **0.45/0.45 = 158/158 จุด**
  (คะแนน 0.384 → 0.237) แต่ CV เวลาต่อรอบยัง 15 % · f ≤ 0.30 ทั้งสองหน้าต่าง จับครึ่งรอบ
- ปั๊มจริงในฐานข้อมูล (LF-600, TE-112 × 2 ชุดสาย ที่ 50 ml/h): f = 0.40 ดีที่สุดอยู่แล้ว

### 9.3 ค่าที่ต่างจากข้อมูลเดิม และ Calibration รอบปั๊มใหม่

ทุกครั้งที่กด "เก็บ" การทดสอบจับรอบปั๊ม (ครบ, ≥ 4 ช่วง) โปรแกรมเทียบคาบที่วัดได้กับข้อมูลเดิมของ ยี่ห้อ + รุ่น + ชนิด + ชุดสาย
- มีข้อมูลที่ rate เดียวกัน: เทียบกับคาบเฉลี่ยของ rate นั้น · ไม่มี: เทียบปริมาตรต่อรอบกับโปรไฟล์
- **ต่างไม่เกิน 25 %** → เก็บรวมเฉลี่ยกับข้อมูลเดิมอัตโนมัติ
- **ต่างเกิน 25 %** → popup "รอบปั๊มต่างจากข้อมูลเดิม" แสดงครั้งนี้/ของเดิม/% ต่าง
  - **เก็บรวมกับข้อมูลเดิม** (add) → นำไปเฉลี่ย · **ไม่เก็บ** (skip — ค่าเริ่มต้น, Esc) → บันทึกไว้แต่ไม่ใช้
  - ต่างติดกันตั้งแต่ 2 ครั้ง → เสนอ **Calibration ใหม่ (แทนที่ข้อมูลเดิม)** ด้วย
- ผลการทดสอบถูกบันทึกเสมอ — คำถามนี้มีผลกับ "การเรียนรู้รอบปั๊ม" อย่างเดียว
- บันทึกทุกครั้งใน `profile_observations`: `out_of_range`, `decision` (auto / add / skip / calibration), `accepted`

**Calibration รอบปั๊มใหม่** (หน้าสร้างการทดสอบ ขั้น 4 → ปุ่ม "Calibration…" หรือช่องขนาดหน้าต่าง → "Calibration รอบปั๊มใหม่")
- แสดงสิ่งที่จำไว้ (ปริมาตรต่อรอบ, หน้าต่างราย rate) และเสนอเรียง rate **จากสูงไปต่ำ** (rate สูงวัดคาบได้ในไม่กี่วินาที)
- rate แรก: วัดคาบก่อนเริ่ม ไม่ใช้ข้อมูลเดิม → กด "เก็บ" แล้ว `profiles.calibrated_at` = เวลาเริ่มของขั้นนั้น
  ปริมาตรต่อรอบเริ่มจากค่านี้ และหน้าต่างที่ปรับไว้ของรุ่นนี้ถูกล้าง
- rate ถัดไป: ใช้ค่าที่เรียนรู้ใหม่ · หน้าต่างราย rate ปรับใหม่จากข้อมูลหลัง `calibrated_at` เท่านั้น
- ข้อมูลเก่าทั้งหมด (ผล, observations) ไม่ถูกลบ — แค่ไม่ถูกใช้เรียนรู้ (สอบย้อนหลังได้)

flow = Δน้ำหนัก / Δเวลา จึงต้องถูกทั้งสองแกน: น้ำหนักต้องมาจากบรรทัดที่ครบ และเวลาต้องเป็นเวลาที่ข้อมูลมาถึงจริง

| โหมด | การทำงาน | เวลาของจุด |
|---|---|---|
| Stream | ตราชั่งส่งเอง โปรแกรมรอรับ | เวลาที่บรรทัดมา **ครบ** (ถึง LF) |
| ถามค่า | ส่งคำสั่ง `Q` ตามจังหวะคงที่ (0.1 s) ล้างบัฟเฟอร์ก่อนถามทุกครั้ง รอคำตอบเต็มบรรทัดได้ถึง `response_timeout_s` (1.0 s) | กึ่งกลางระหว่างเวลาส่งกับเวลาที่คำตอบมาครบ |
| อัตโนมัติ | ฟัง 1 s ถ้ามีข้อมูลเข้า = Stream ไม่งั้นลองถาม ถ้าตอบ = ถามค่า | — |

## 11. Workflow ของแต่ละโหมด

ทั้งสามโหมดใช้ engine ตัวเดียวกัน ต่างกันที่ค่าเริ่มต้นและจำนวนขั้น

| | Calibration | Inspection | Quick Test |
|---|---|---|---|
| จำนวน rate | 3 (เพิ่ม/ลบได้) | 1 | 1 |
| rate เริ่มต้น — infusion | 10, 50, 200 ml/h | 50 ml/h | 50 ml/h |
| rate เริ่มต้น — syringe | 10, 50, 100 ml/h | 50 ml/h | 50 ml/h |
| เวลาต่อ rate | 15 นาที | 5 นาที | 2 นาที |
| วิธีจับเริ่มต้น | infusion: จับรอบปั๊ม · syringe: จับตามเวลาแบ่งช่วง | เหมือนกัน | เหมือนกัน |
| เกณฑ์ยอมรับเริ่มต้น | infusion ± 5 % · syringe ± 3 % | เหมือนกัน | เหมือนกัน |

**ลำดับการทำงาน**

1. (ถ้าต้องการ) ทำ self-check ของวันนั้น
2. สร้างการทดสอบ: ข้อมูลเครื่อง → ตรวจเครื่อง → โหมด → ตั้งค่า
3. กดเริ่มขั้นที่ 1 → (pre-run) → วัดจริง — ข้อมูลดิบถูกเขียนลงดิสก์ทุก ~1 วินาทีระหว่างรัน
4. จบขั้น → โปรแกรมถาม **เก็บผล / ไม่เก็บ**
   - เก็บ: บันทึกลงฐานข้อมูล ถ้าทดสอบครบเวลาจะเลื่อนไปขั้นถัดไป
   - ไม่เก็บ: ลบข้อมูลของขั้นนั้นถาวร ขั้นเดิมยังอยู่ กดเริ่มคือทำซ้ำ
   - ถ้าหยุดกลางคันแล้วเลือกเก็บ: บันทึกเป็นผล "ไม่ครบ" และยังต้องทำขั้นนั้นใหม่
5. Calibration ถามแบบนี้ทุก rate แล้วหยุดรอให้ปรับปั๊มก่อนเริ่มขั้นถัดไป
6. ปิดโปรแกรมขณะรันหรือขณะรอคำตอบ: การทดสอบนั้นไม่ถูกเก็บ

ไฟล์: `services/session_controller.py`
