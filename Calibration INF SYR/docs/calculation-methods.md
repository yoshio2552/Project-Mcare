# DeltaM — โมเดลคณิตศาสตร์และ workflow ของการทดสอบ

เอกสารนี้อธิบายสิ่งที่โปรแกรม **ทำอยู่จริงในเวอร์ชัน 0.3.0**
ตัวเลขในวงเล็บคือค่าเริ่มต้น ปรับได้ในหน้าตั้งค่า ไฟล์อ้างอิงอยู่ท้ายแต่ละหัวข้อ

สถานะการตรวจสอบ: ทุกสูตรผ่าน unit test (42 ข้อ) และตราชั่งจำลองแล้ว
**ยังไม่ได้ยืนยันกับตราชั่งและปั๊มจริง** — หัวข้อที่พึ่งข้อมูลจริงมากที่สุดคือ 7.2, 7.3, 8 และ 9

## 1. ภาพรวมเส้นทางข้อมูล

```
ตราชั่ง → (t, w) ทีละจุด                                                 (หัวข้อ 10)
   │
   ├─ [ช่วงก่อนวัด]  ถ้าตั้งไว้ — ข้อมูลใช้ดูความพร้อม ไม่นำไปคิดผล        (หัวข้อ 7)
   │
   └─ [ช่วงวัดจริง]  เริ่มนับเวลาใหม่จาก 0
        1. ทิ้งข้อมูลช่วงแรก (2 s)
        2. คำนวณ slope = flow ขณะนั้น                                   (หัวข้อ 3)
        3. วิธีจับ ตัดสินว่า "จบ 1 ช่วงวัดหรือยัง"                         (หัวข้อ 4)
        4. อัปเดตสถิติของทุกช่วงวัด                                      (หัวข้อ 5)
        5. ตัดสิน PASS / FAIL                                          (หัวข้อ 6)
   จบขั้น → ถามผู้ใช้ว่าเก็บผลหรือไม่                                     (หัวข้อ 11)
```

`t` = เวลา (วินาที), `w` = น้ำหนักบนตราชั่ง (กรัม)

ค่าคำนวณทั้งชุดของแต่ละขั้นถูก **คัดลอกตอนกดเริ่ม** และบันทึกไปกับผล
การแก้หน้าตั้งค่าระหว่างรันไม่มีผลกับการทดสอบที่กำลังเดิน

## 2. การแปลงน้ำหนักเป็น flow และค่าแก้

```
Q = (Δw / Δt × 3600 − B) / ρ          [ml/h]
E = (Q − Q_target) / Q_target × 100    [%]
```

| สัญลักษณ์ | ความหมาย | ที่มา |
|---|---|---|
| `ρ` | ความหนาแน่นของเหลว (g/ml) | ถ้ากรอก **อุณหภูมิของเหลว** ในฟอร์ม (0–40 °C): คำนวณจากสูตรความหนาแน่นน้ำของ Tanaka (2001) · ถ้าไม่กรอก: ค่าในหน้าตั้งค่า (0.9982) |
| `B` | อัตราน้ำหนักพื้นฐาน (g/h) | จาก self-check ที่ **ผ่าน** ของวันนั้น (หัวข้อ 8) · ถ้าไม่มี: 0 |

- ตัวอย่าง ρ: 20 °C = 0.99821, 25 °C = 0.99705
- `B` เป็นค่าลบเมื่อมีการระเหย (น้ำหนักหาย) การหักค่าลบทำให้ flow ที่แก้แล้วสูงขึ้น
- flow ที่คำนวณได้ติดลบจะถูกปัดเป็น 0
- ผลแต่ละขั้นบันทึกว่าใช้ ρ จากไหน และ B เท่าไร
- **ยังไม่มี:** ค่าแก้แรงลอยตัวของอากาศ (ราว 0.1 %) และงบความไม่แน่นอนของการวัด

ไฟล์: `core/stats.py`, `core/corrections.py`

## 3. Slope (flow ขณะนั้น)

เส้นตรง least-squares ผ่าน N จุดล่าสุด แล้วแปลงด้วยสูตรในหัวข้อ 2

```
slope = (N·Σtw − Σt·Σw) / (N·Σt² − (Σt)²)      [g/s]
```

- จำกัดค่าสูงสุดไว้ที่ 5 × rate ที่ตั้ง แสดงเมื่อมีอย่างน้อย 10 จุด
- **แสดงผลทุกวิธีจับ** (ให้เห็นรูปแบบการไหล) แต่ **ใช้คำนวณ** เฉพาะวิธีจับรอบปั๊ม
- N มาจากไหน: ดูหัวข้อ 9

ไฟล์: `core/stats.py` (`regression_slope`), `core/engine.py` (`_SlopeWindow`)

## 4. วิธีจับ (แบ่งช่วงวัด)

flow ของ 1 ช่วงวัดทุกวิธีใช้สูตรในหัวข้อ 2 กับจุดต้น–ปลายของช่วง ต่างกันที่จุดต้น–ปลายมาจากไหน

### 4.1 จับรอบปั๊ม (peak-to-peak) — `pump_cycle`

**เริ่มทำงานเมื่อ** หน้าต่าง slope เต็ม N จุดแล้ว

**หาจุดกลับตัว** เก็บ slope ไว้ในหน้าต่างกว้าง `2·n_bar + 1` จุด
- จุดกึ่งกลางเป็นค่าสูงสุดของหน้าต่าง → **TOP** · เป็นค่าต่ำสุด → **DOWN** · ค่าเท่ากันหมด → ไม่นับ
- จึงรู้ผลช้ากว่าเหตุการณ์จริง n_bar จุด

**กฎการสลับ** TOP กับ DOWN ต้องสลับกันเสมอ ถ้าเจอชนิดเดิมซ้ำ จะไม่รายงาน
แต่เลื่อนจุดอ้างอิงไปยังตัวที่ดีกว่า (TOP เลือก slope สูงกว่า, DOWN เลือก slope ต่ำกว่า)

**1 รอบปั๊ม** = จุดกลับตัวชนิดเดียวกัน 2 จุดติดกัน จึงมี 2 สายซ้อนกัน (สาย A และ B เหลื่อมกันครึ่งรอบ)

**เงื่อนไขจบ**
- ตามเวลา: เวลาจากจุดเริ่มของสายถึงปลายรอบล่าสุด ≥ เวลาที่ตั้ง ทั้งสองสาย (ตรวจที่ปลายรอบ จึงไม่ตัดกลางรอบ)
- ตามจำนวนรอบ: แต่ละสายครบ N รอบ ทั้งสองสาย (ตั้ง 30 รอบ = 60 ช่วงวัด)

ไฟล์: `core/cycle_analyzer.py`, `core/strategies/pump_cycle.py`

### 4.2 จับตามเวลา แบ่งเป็นช่วง — `time_interval`

จุดเริ่ม = จุดแรกหลังทิ้งข้อมูลช่วงแรก · ตัดช่วงทุก L วินาที (เลือกได้เฉพาะค่าที่หารเวลาทดสอบลงตัว)
· จบเมื่อครบ `เวลาทดสอบ / L` ช่วง · กราฟ slope ยังแสดงอยู่ แต่ไม่มีจุด peak/valley

### 4.3 จับตามเวลา วัดรวดเดียว — `time_total`

เหมือน 4.2 แต่ L = เวลาทดสอบทั้งหมด ได้ช่วงวัดเดียว (จึงไม่มี CI และ SD)

ไฟล์: `core/strategies/time_based.py`

## 5. สถิติของช่วงวัด

คิดจาก **ทุกช่วงวัด** ตั้งแต่เริ่มการทดสอบ (n = จำนวนช่วง, s = ส่วนเบี่ยงเบนมาตรฐานตัวอย่าง)

| ค่า | สูตร | แสดงเป็น |
|---|---|---|
| Flow เฉลี่ย | `Q̄ = ΣQ / n` | ml/h |
| CI 95 % | `t(0.975, n−1) · s / √n` | ± % ของ rate ที่ตั้ง |
| 2 SD | `2 · s` | ± % ของ rate ที่ตั้ง |

ค่าเดียวกันนี้คิดกับระยะเวลาของแต่ละช่วงด้วย แสดงเป็นวินาที (การ์ดเวลาต่อรอบปั๊ม)

ไฟล์: `core/stats.py`, `core/engine.py` (`_compute_stats`)

## 6. การตัดสิน PASS / FAIL

```
E = (Q̄ − Q_target) / Q_target × 100         PASS เมื่อ |E| ≤ เกณฑ์ยอมรับ
```

- `Q̄` = ค่าเฉลี่ยของช่วงวัดที่ **ครบสมบูรณ์** เท่านั้น (ถ้ายังไม่มีเลย ใช้ค่าเฉลี่ยสะสมแทน)
- ถ้าการทดสอบถูกหยุดก่อนครบ ผลติดป้ายว่า "ไม่ครบ"
- **ค่าเฉลี่ยสะสม (สด)** บนการ์ดกลาง = flow จากจุดเริ่มของสายถึงตอนนี้ แกว่งตามจังหวะรอบปั๊ม จึง **ไม่ใช้ตัดสิน**

ไฟล์: `core/engine.py` (`current_error`, `verdict`)

## 7. ช่วงก่อนวัด (pre-run)

ข้อมูลช่วงนี้บันทึกแยกใน `prerun.csv` และไม่เข้าการคำนวณผล เมื่อเข้าช่วงวัดจริงทุกอย่างเริ่มนับใหม่

### 7.1 เงื่อนไขเข้าช่วงวัดจริง

| โหมดเริ่มวัด | เข้าเมื่อ |
|---|---|
| ทันที | จุดแรก (ไม่มี pre-run เว้นแต่ต้องวัดคาบรอบปั๊มก่อน) |
| หลังปล่อยรันตามเวลา | เวลาผ่านไป ≥ ค่าที่ตั้ง |
| อัตโนมัติเมื่อ flow นิ่ง | ผ่านเกณฑ์ในหัวข้อ 7.3 |
| กดปุ่มเอง | ผู้ใช้กด "เริ่มวัดเดี๋ยวนี้" |

ทุกโหมดกด "เริ่มวัดเดี๋ยวนี้" เพื่อข้ามได้

### 7.2 การวัดคาบรอบปั๊ม

ใช้เมื่อวิธีจับ = จับรอบปั๊ม และยังไม่มีค่าคาบจากโปรไฟล์ (หรือผู้ใช้เลือก "วัดก่อนเริ่มทุก rate")

1. นำน้ำหนักช่วง pre-run มาลบเส้นตรงแนวโน้ม เหลือเฉพาะส่วนที่แกว่งตามรอบปั๊ม
2. คำนวณ autocorrelation ของส่วนที่เหลือ
3. คาบ P = ระยะเลื่อนที่ autocorrelation ขึ้นยอดครั้งแรกหลังผ่านศูนย์
4. ยอมรับ P เมื่อครบทุกข้อ
   - มีข้อมูล ≥ 30 s และยาว ≥ 3 เท่าของ P
   - ค่าสหสัมพันธ์ที่ยอด ≥ 0.5
   - ขนาดการแกว่ง ≥ 3 เท่าของความละเอียดตราชั่ง
   - ประเมิน 2 ครั้งติดกัน (ห่างกัน 5 s) ได้ค่าต่างกันไม่เกิน 5 %
5. ถ้าหาไม่ได้ภายใน 300 s → ใช้ขนาดหน้าต่างที่กำหนดเอง และบันทึกหมายเหตุไว้ในผล

ผลกับสัญญาณจำลองคาบ 8–150 s: คลาดไม่เกิน 1 %

### 7.3 การตรวจ flow นิ่ง (โหมดเริ่มอัตโนมัติ)

แบ่งข้อมูลล่าสุดเป็น K ช่วงติดกัน (K = 4) ช่วงละ T วินาที
(T = คาบรอบปั๊มถ้ารู้ เพื่อให้การแกว่งตามรอบหักล้างกัน · ไม่รู้ใช้ 15 s) แล้วดูน้ำหนักที่เพิ่มในแต่ละช่วง

| ค่า | สูตร |
|---|---|
| ความแกว่ง V | `(มากสุด − น้อยสุด) / ค่าเฉลี่ย × 100` |
| แนวโน้ม D | `|ค่าเฉลี่ยครึ่งหลัง − ค่าเฉลี่ยครึ่งแรก| / ค่าเฉลี่ย × 100` |
| เกณฑ์ L | `เกณฑ์พื้นฐาน (2 %) + 2 × ความละเอียดตราชั่ง / น้ำหนักที่เพิ่มต่อช่วง × 100` |

**นิ่ง เมื่อ `V ≤ L` และ `D ≤ L / 3`**

- ส่วนที่บวกเข้าเกณฑ์ คือความแกว่งที่มาจากการปัดเศษของตราชั่งล้วนๆ
  (ที่ 10 ml/h บนตราชั่งละเอียด 1 mg ช่วง 15 s เพิ่มเพียง 41 mg การปัดเศษอย่างเดียวทำให้ดูแกว่งเกิน 2 %)
- เงื่อนไขแนวโน้มกัน flow ที่ไหลขึ้น/ลงช้าๆ แต่แต่ละช่วงยังดูใกล้กัน
- ความละเอียดตราชั่งประเมินจากขั้นเล็กที่สุดที่เห็นในข้อมูล

**สถานะตามหลักการ:** เป็นกฎเชิงปฏิบัติที่อธิบายได้ ไม่ใช่การทดสอบทางสถิติเต็มรูป
เท่าที่ทราบ IEC 60601-2-24 ใช้วิธีกำหนดช่วงเวลาให้เครื่องเดินก่อนวิเคราะห์ ไม่ได้ใช้การตรวจนิ่ง
ถ้าต้องอ้างมาตรฐาน ให้ใช้โหมด "หลังปล่อยรันตามเวลา" (ควรเปิดมาตรฐานยืนยันก่อนใช้อ้างอิง)

ไฟล์: `core/prerun.py`

## 8. Self-check (การระเหย + การไหลของค่าตราชั่ง)

**ทำอย่างไร** จัดบีกเกอร์เหมือนตอนทดสอบจริง หยุดปั๊ม บันทึกน้ำหนักตามเวลาที่ตั้ง (10 นาที)

**คำนวณ** (ทิ้ง 2 s แรก)

| ค่า | สูตร |
|---|---|
| อัตราพื้นฐาน B | ความชันของเส้นตรง least-squares ของน้ำหนักเทียบเวลา (g/h) |
| ความคลาดเคลื่อนมาตรฐานของ B | `SD ของส่วนเหลือ / √Σ(t − t̄)²` |
| noise ของตราชั่ง | SD ของส่วนเหลือรอบเส้นตรง |

B รวมการระเหยและการไหลของค่าตราชั่งไว้ด้วยกัน (แยกไม่ได้และไม่จำเป็น เพราะหักรวมกัน)

**ผ่านเมื่อครบทุกข้อ** (เป็นข้อเสนอ ปรับได้ในหน้าตั้งค่า)
- บันทึกครบเวลาที่ตั้ง
- อัตราของครึ่งแรกกับครึ่งหลังต่างกัน ≤ 30 mg/h (แปลว่านิ่งแล้ว)
- |B| ≤ 500 mg/h (มากกว่านี้ไม่น่าใช่การระเหย)

**การใช้** ผลที่ผ่านใช้เป็น B ในหัวข้อ 2 กับทุกการทดสอบของ **วันเดียวกัน** โดยอัตโนมัติ
ใช้ผลครั้งล่าสุดของวัน ถ้าครั้งล่าสุดไม่ผ่านจะไม่ใช้ค่าแก้ · self-check ที่ถูกยกเลิกไม่ถูกบันทึก

**ข้อจำกัดที่รู้:** ถ้าการระเหยน้อยและตราชั่งละเอียด 1 mg เวลา 10 นาทีจะหยาบเกินไป ควรตั้งให้นานขึ้น

ไฟล์: `core/corrections.py`, `services/session_controller.py` (`start_self_check`)

## 9. ขนาดหน้าต่างคำนวณ และโปรไฟล์ปั๊ม (เฉพาะวิธีจับรอบปั๊ม)

หน้าต่าง slope (N) และ n_bar ต้องพอดีกับคาบรอบปั๊ม: `N = n_bar = คาบ × 0.4 / ช่วงเวลาต่อจุด`

**คาบมาจากไหน** (เลือกใน wizard ช่อง "ขนาดหน้าต่างคำนวณ")

| ตัวเลือก | พฤติกรรม |
|---|---|
| จากโปรไฟล์ปั๊ม (ค่าเริ่มต้น) | มีโปรไฟล์: ใช้ทันที ไม่ต้องรอ · ไม่มี: วัดก่อนเริ่ม (หัวข้อ 7.2) แล้วจำไว้ |
| วัดก่อนเริ่มทุก rate | วัดใหม่ทุกครั้ง |
| กำหนดเอง | ใช้ค่า N และ n_bar ในหน้าตั้งค่า (250 / 250) |

**โปรไฟล์ปั๊ม** = สิ่งที่จำไว้ต่อ ยี่ห้อ + รุ่น + ชุดสาย

- สมมติฐาน: ปั๊มแบบ finger ส่งของเหลวต่อรอบเกือบคงที่
  `ปริมาตรต่อรอบ (ml) = flow × คาบ / 3600` → `คาบ ณ rate ใดๆ = ปริมาตรต่อรอบ × 3600 / rate`
- ทุกการทดสอบแบบจับรอบปั๊มที่ **เก็บผล** (ครบเวลา, ≥ 4 ช่วงวัด) เพิ่มข้อสังเกต 1 รายการ: (rate, คาบที่วัดได้)
- การหาคาบสำหรับ rate ที่จะทดสอบ
  1. เคยวัดที่ rate นี้ (± 2 %) → ใช้ค่าเฉลี่ยของที่เคยวัดจริง
  2. ไม่เคย → คำนวณจากปริมาตรต่อรอบ
- การกันข้อมูลเสีย
  - คาบต่างจากที่เคยวัดที่ rate เดียวกันเกิน 25 % → ไม่จำ (น่าจะจับรอบพลาด)
  - ปริมาตรต่อรอบต่างจากโปรไฟล์เกิน 25 % → จำไว้ใช้ **เฉพาะ rate นั้น** ไม่รวมเข้าโปรไฟล์

**สถานะ:** สมมติฐานปริมาตรต่อรอบคงที่ยังไม่ได้ยืนยันกับเครื่องจริง ถ้าไม่จริง ระบบยังทำงานได้
เพราะจะจำคาบแยกราย rate แต่จะต้องวัดก่อนเริ่มในครั้งแรกของทุก rate
**ยังไม่มี:** การเล่นซ้ำข้อมูลเพื่อหาอัตราส่วนหน้าต่างที่ดีที่สุดต่อรุ่น (ใช้ 0.4 ทุกรุ่น)

ไฟล์: `core/profiles.py`, `services/session_store.py` (`expected_period`, `add_observation`)

รองรับหน่วย g mg kg) ถ้าไม่ตรงจะใช้ตัวเลขตัวแรกของบรรทัด

## 11. Workflow ของแต่ละโหมด

ทั้งสามโหมดใช้ engine ตัวเดียวกัน ต่างกันที่ค่าเริ่มต้นและจำนวนขั้น

| | Calibration | Inspection | Quick Test |
|---|---|---|---|
| จำนวน rate | 3 (เพิ่ม/ลบได้) | 1 | 1 |
| rate เริ่มต้น — infusion | 10, 50, 200 ml/h | 50 ml/h | 50 ml/h |
| rate เริ่มต้น — syringe | 10, 50, 100 ml/h | 50 ml/h | 50 ml/h |
| เวลาต่อ rate | 15 นาที | 5 นาที | 2 นาที |
| วิธีจับเริ่มต้น | infusion: จับรอบปั๊ม · syringe: จับตามเวลาแบ่งช่วง | เหมือนกัน | เหมือนกัน |
| เกณฑ์ยอมรับเริ่มต้น | infusion ± 5 % · syringe ± 3 % | เหมือนกัน | เหมือนกัน |

**ลำดับการทำงาน**

1. (ถ้าต้องการ) ทำ self-check ของวันนั้น
2. สร้างการทดสอบ: ข้อมูลเครื่อง → ตรวจเครื่อง → โหมด → ตั้งค่า
3. กดเริ่มขั้นที่ 1 → (pre-run) → วัดจริง — ข้อมูลดิบถูกเขียนลงดิสก์ทุก ~1 วินาทีระหว่างรัน
4. จบขั้น → โปรแกรมถาม **เก็บผล / ไม่เก็บ**
   - เก็บ: บันทึกลงฐานข้อมูล ถ้าทดสอบครบเวลาจะเลื่อนไปขั้นถัดไป
   - ไม่เก็บ: ลบข้อมูลของขั้นนั้นถาวร ขั้นเดิมยังอยู่ กดเริ่มคือทำซ้ำ
   - ถ้าหยุดกลางคันแล้วเลือกเก็บ: บันทึกเป็นผล "ไม่ครบ" และยังต้องทำขั้นนั้นใหม่
5. Calibration ถามแบบนี้ทุก rate แล้วหยุดรอให้ปรับปั๊มก่อนเริ่มขั้นถัดไป
6. ปิดโปรแกรมขณะรันหรือขณะรอคำตอบ: การทดสอบนั้นไม่ถูกเก็บ

ไฟล์: `services/session_controller.py`
